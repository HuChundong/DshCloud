# 右侧面板（artifact panel）设计

> 状态：提案，未实现。英文版待设计冻结后补。
> 分支：`feat/artifact-panel`，包位置 `packages/dsh-artifact-panel`。

## 一句话

**右侧只放两种东西：用户主动开的工具，和 agent 被动产出的结果。**

这句话是整份设计的裁决标准。任何一个想进来的东西，先问它是哪一类；两类都不是，就不进这个面板。克制体现在这条判据的存在，而不是功能的数量。

## 组织原则：主动与被动

面板里的 tab 按**来源**分成两类，这是整个产品形态的骨架。

**主动**——用户自己要用的工具，长期驻留：

- 目录树
- 控制台
- 浏览器

**被动**——会话过程中 agent 产出的结果，用户查看：

- 产出文件的预览（markdown / 代码 / 图片 / HTML）

同类产品常见的失败模式是把所有面板做成**平权的 tab**：文件树、终端、Git、子代理、编辑器并排堆在一条 tab 栏里，没有任何原则说明谁该在那儿。一旦平权，加下一个就没有理由拒绝，面板最终长成一个什么都有的工作台。

主动/被动的二分给了拒绝的理由：**一个新 tab 要么是用户会主动去开的工具，要么是 agent 会产出的结果，两者都不是就不进这个面板。**

### 明确不做的

| 不做 | 理由 |
|---|---|
| Git 面板 | 既非工具也非产物，属会话叙事，归左侧 |
| 子代理拓扑 / 后台任务 | 同上 |
| 底部面板 / 拖拽分栏 / 跨面板合并 | 布局系统一旦引入就会长成 IDE，且自带一套持久化与陈旧状态清理 |
| 文件编辑 | 编辑器是 agent。人想改，说一句话比打开编辑器快（**待定**） |
| Office / PDF 预览 | 依赖体积大、收益低，留到有人真的要 |

### tab 栏的规则

```
[文件] [终端] [报告.md] [dashboard.html ×]
                                  ↑ 仅当前 tab 显示关闭键
```

**所有 tab 一律可开可关，包括文件树。** 主动/被动是**判据**（什么东西有资格进这个面板），不是 tab 的行为差异——没有"固定 tab"这个概念，用户想关掉文件树就该能关掉。

- 关闭键只在当前 tab 上出现，不占非活动 tab 的宽度；
- **按路径去重**：同一文件反复产出只占一个 tab；
- **不做自动淘汰**：tab 累积，由用户关。

主动 tab 从**面板的空状态**开：面板打开而一个 tab 都没有时，中间列出三个选项——文件、终端、浏览器。这比一个 `+` 菜单更直接，且空面板不会是一片空白。

保留的顾虑：无上限累积仍有 tab 泛滥的风险。先按上面的规则做，观察真实使用后再决定要不要加上限。

### 面板本身的开关

面板是可开可关的，入口按会话状态分两处：

- **无会话**（首页 / 新会话态）：窗口**右上角**一个按钮。当前那片区域是空的，位置现成。
- **会话中**：标题栏左侧区域，与"轨迹"按钮相邻。

两处点击后都是打开面板；面板已开时按钮变为收起。

### 被动不等于自动弹出

**产物是被"列出来"，不是被"推过来"。** agent 产出文件后，对话里出现产出文件的入口（dsh 自带，见下），用户点了才在右侧开 tab。

理由：自动切换会抢焦点、打断正在看的东西，并且需要一整套"钉住 / 取消钉住"的状态机来让用户夺回控制权。列出可点没有这些问题，用户的注意力始终由用户自己支配。

### 面板默认不存在

会话产出第一个东西、或用户主动开第一个工具之前，右侧不占宽度。纯聊天的会话不该被一个空面板占掉三分之一屏幕。

## 被动这一半几乎不用我们渲染

dsh 的 `ui-deliverables` **已经**在每轮末尾渲染了产出文件的 chip 行。我们不需要自己算产出、不需要渲染任何列表——只需要把点击接管过来。

接管点是 `ctx.workspaces.openPath`：对话里所有文件打开都汇入这一个方法（工具行的路径链接、产出文件 chip、正文里的文件提及，都由 `ui-conversation` 解析成绝对路径后调它），而它默认把文件交给宿主操作系统——在沙箱里等于什么都不做。包一层即可：

```js
const original = workspaces.openPath   // 必须是原始引用，不是 bound 副本
workspaces.openPath = (path) => { ... }
```

存原始引用而非 bound 副本是有原因的：可能有多个插件包同一个方法，只有还原原始引用才能让任意顺序的卸载都不破链。

**接管不了就必须放行。** 面板被互斥停用、还没挂载、或者当前没有会话时，包装层要原样调用 `original`，而不是吞掉这次调用。一个开不了文件的面板去拦截"打开文件"，症状是用户点了以后什么都没发生——比不拦截更糟。这跟"选不出 viewer 就落到下载兜底"是两回事：那条管的是已经进了面板之后，这条管的是压根该不该进。

轮末尾还是一条带优先级的渲染链，可以抢在 `ui-deliverables` 之前渲染自己的 chip 行。**我们不这么做**：既然 `openPath` 已经被包了，原生 chip 点下去就已经进面板，替换那行 UI 只会多一处对上游渲染结构的耦合。

### 联动的完整行为

包住 `openPath` 之后，被动侧的联动规则：

1. **一个入口，多个来源**。产出文件 chip、工具行的路径链接、正文里的文件提及，全都汇入同一个方法，因此全都自动获得同样的行为——不需要为每种来源单独接线。
2. **面板关着就打开它**。用户点了文件却什么都没发生是最糟的结果。打开面板、开 tab、聚焦，一次完成。
3. **按路径去重**。同一文件重复点只聚焦已有 tab，不新开。
4. **viewer 由扩展名/MIME 选**，选不出来的落到"下载"兜底，不留空白 tab。
5. **会话切换时换掉整组 tab**。tab 属于会话，不属于窗口；切回上一个会话应看到它原来的 tab。
6. **不抢焦点**：只有用户点击才开 tab，agent 产出本身不触发任何面板动作。

第 6 条是被动的定义本身，前 5 条是让它不难用。

### 附：产出信号的语义（背景）

暂时用不上，但解释了这个信号的边界，将来若要做自动跟随或产物聚合会需要。

dsh 的会话快照里，`tool-result` 节点带一个 `callView`：

```
{ card: 'diff' | 'generic', kind: 'edit', locations: [{ path }] }
```

`ui-deliverables` 据此决定什么算产出：**只有渲染意图为 diff 卡或 edit 型 generic 卡的工具结果才算，读取、删除、失败一律不算**，并在轮边界（用户消息，或 `turn` 号变化）重置累积。

它的盲区是 `bash: python gen.py > report.html` 这类经由 shell 产出的文件——tool-result 不带 edit 卡，不计入产出。曾考虑用 fs.watch 补上，结论是不值得：那需要一整套忽略清单和排序启发式，用面板 80% 的复杂度去换 20% 的场景。真需要时，那条路径本来就渲染在对话里，点一下就打开。

给 agent 一个 `preview_file` 动词留给 v2——它要改 agent 契约，先看不改契约的版本够不够。

## 数据平面：走 envd，插件因此没有 host 半

文件平面走 envd，不走隧道：envd 的接口已经完备，不需要在沙箱里再实现一遍。

这个选择有一个连带效果，比接口完备本身更值钱：**插件不需要 host 半了。**

因为 envd 是网关从沙箱外部寻址的（`Host: 49983-<sandboxId>.<domain>` 经 CubeProxy），而 dsh 插件的 host 半跑在沙箱**内部**——让内部进程绕出去再绕回来毫无意义。所以数据平面是：

```
浏览器 → 网关 /sandbox/fs/*  →  CubeProxy  →  envd
```

网关侧本来就有 `callerOf(req)` 解析调用者、`sandboxes.ensure(username, caller.id)` 拿 `sandboxId` 的现成路径（`/sandbox/restart` 就是这么写的），**不经过隧道**。于是：

- 不需要 `connection.rpc.handle` 注册通道；
- 不需要 cordis host 插件，不需要 `package.json` 的 host 入口；
- 不需要给 dsh 的新通道加 nginx location；
- 网关路由是我们自己的 JS，完全可控。

`packages/dsh-artifact-panel` 因此是一个**纯浏览器包**。envd 的调用全部落在 `gateway/src/envd.js`。

额外收益：面板在 dsh 后端还没起来时也能工作（envd 与后端存活无关），冷启动时租户能先看见工作区里已有的东西。

### 三个主动 tab 正好都落在 envd 上

| tab | 靠什么 | 状态 |
|---|---|---|
| 目录树 | `ListDir { path, depth }`（unary） | 直接可用 |
| 预览取文件 | `GET /files?path=<绝对路径>` + `Stat` | 直接可用 |
| 控制台 | envd 的 PTY 服务 | **需要流式支持** |
| 浏览器 | iframe；地址走 CubeProxy 的 `<port>-<sandboxId>.<domain>` 虚拟主机 | 目标待定 |

`envd.js` 已有 Connect 信封编解码与 CubeProxy 寻址，`Stat` / `ListDir` 各十行。

`readFile` 要多一步：现在的 `envdRequest` 把 `method: 'POST'` 写死了，也不接受查询串，而取文件走的是 envd HTTP 的 `GET /files?path=`。得先把这个函数一般化。改动不大，但它是 `startBackend` 唯一的生命线——沙箱起不来就是这条路断了——所以改的时候别顺手重构它。

**控制台是唯一有真实工作量的一个。** 现在的 `envdRequest` 在 `response.on('end')` 之后一次性解码完整 body，长连接流会一直阻塞到超时——`runCommand` 能用只是因为它跑的是立即返回的命令。终端要双向流，必须给 `envd.js` 加一条流式路径，并在网关开一个 WebSocket 端点桥接。

走 envd 的 PTY 意味着**沙箱里不需要装任何原生终端依赖**，也不需要在镜像里处理它在 snapshot/restore 中的行为。

**浏览器 tab 改成了画布。** 原来的两个选项——看 dev server、或上外网——都被放弃了，换成"看 agent 正在做的页面"。

这不是把它做简单了，是把它挪回了该在的那条线上：面板的判据是"用户主动开的工具，和 agent 被动产出的结果"，dev server 浏览器是背后拖着一台机器的工具，而画布就是**产出本身**。

代价上的差别是整整一个数量级。反向代理、泛域名证书、绝对路径重写、WebSocket 转发、出口边界——那些**全部只为了伺候一个 dev server**，静态页面一个都不需要。而画布要的东西已经建好了：`/sandbox/preview/<票>/<路径>` 带 CSP sandbox，相对资源实测可用。

两个已定的取舍：

- **允许联外网**。CSP 只有 `sandbox` 指令（拿掉同源），不限制 `script-src`／`connect-src`，所以 agent 写的页面可以引 CDN 上的图表库。这是明确选择而不是疏漏——收紧它会直接限制 agent 能产出什么。
- **画布内部跟随**。它每两秒问一次哪个页面最新、有没有被改写，变了就重载。这是对"不抢焦点"的**故意破例**，但破得住：打开画布这个 tab 本身就是用户在说"把你在做的东西给我看"。它仍然不会自己弹开面板，也不碰任何别的 tab。

跟随用的是**最近修改时间**而不是对话自己的产出信号。后者更精确，但盲区恰好在画布输不起的地方：经 shell 重定向产出的页面（`python gen.py > report.html`）不带 edit 卡，永远不会出现在那条信号里。

### 两条必须做对的约束

**一、只能传绝对路径。** `Dockerfile` 里的 `ENV HOME` 是容器环境变量，不是 `/etc/passwd` 里 root 的 home；envd 解析相对路径靠 passwd，`path=notes.md` 会落到 `/root/notes.md`。网关直接拒绝相对路径，不做猜测性拼接。

**二、路径钉在工作区（`/mnt/workspace`）之内，但这是"范围"不是"防线"。** 这一条先前写反过，更正如下。

真正的安全属性只有一条，而且不在路径处理里：**`callerOf` 解析调用者、`sandboxes.ensure` 交回的是那个调用者自己的沙箱**，所以一个请求只可能打到发起它的租户自己的机器上。跨租户读取不是"被防住了"，是无法表达。

**沙箱内部没有什么需要防的。** 边界就是沙箱本身；在自己的沙箱里租户已经是 root——agent 就是一个他们能打字进去的 root shell。任何能骗面板读到的东西，他们开口就能读到。

所以这个根的作用是让它成为一个**工作区浏览器**而不是文件系统浏览器，并且让路径保持绝对、有根，路由永远不用猜。

**因此软链不追。** 早先的版本对每个路径做 `realpath` 再校验一次结果，理由是挡住工作区里指向别处的链接。那买不到任何安全性——同一份内容跟 agent 说一句话就能拿到——却在每个请求上多一趟往返，而且行为是错的：租户故意把自己的目录链进自己的工作区，本来就该能打开。现在它能打开了。

顺带更正两个具体事实：

- `/app/sandbox/env.sh` **不敏感**。它是 `Dockerfile` 末尾的白名单投影，只有 `PATH` / `DSH_HOME` / `TZ` / `NODE_ENV` 这类镜像期变量；在活沙箱里 grep `DEEPSEEK|API_KEY|TOKEN`，命中数为 0。
- `/proc/<后端pid>/environ` 里确实有 `DEEPSEEK_API_KEY`（**整个部署共享的模型凭据**）和 `SANDBOX_TOKEN`。但**租户本来就能读到它**——`printenv` 而已。这是先于面板存在的问题，面板挡不挡都一样。真要堵，方向是让后端从不落进进程环境的地方取凭据，那是另一件工程，跟这个面板无关。

会话 cwd 的解析放在客户端——`ctx.sessions` 里有每个会话的 `cwd`，相对路径在浏览器侧先解析成绝对路径再发给网关。

## HTML 预览：同源加 CSP sandbox

不需要给预览一个独立 origin（例如 CubeProxy 的端口虚拟主机）。同源路径前缀配合响应头就够：

```
content-security-policy: sandbox allow-scripts allow-popups allow-downloads allow-modals; object-src 'none'
x-content-type-options: nosniff
referrer-policy: no-referrer
```

`sandbox` 指令**不含 `allow-same-origin`**，浏览器强制给它一个不透明源，拿不到同源访问。iframe 的 `sandbox` 属性是第一道边界，这个头是纵深防御——即使被弹窗顶层打开也守得住。

预览 URL 必须用**路径编码**而不是查询参数：查询编码会在浏览器解析相对路径时丢掉会话 scope，被预览页面的 `./style.css`、`img/x.png` 就会 404。

## 怎么挂上去：body 级 portal

**整面板 slot 由 `ui-layout` 独占**，插件拿不到。所以面板自己挂一个 body 级宿主，用自己的 React root 和 fixed 定位：

```js
const host = document.createElement('div')
host.setAttribute('data-dsh-artifact-panel', '')
document.body.appendChild(host)
```

这不是权宜之计，是这个平台上唯一的路。随之而来的约定：

- **根锚点带 data 属性**，皮肤和外部 CSS 靠它做作用域覆盖，不波及宿主；
- **布局变量写在 `<html>` 上**，面板打开时有效，拖拽期间逐帧更新；
- **z-index 压在宿主浮层栈之下**：DSH 的浮层在 100 / 1000+，面板取 40 一档，任何弹窗天然盖住面板；
- **类名不是契约**：CSS Modules 哈希会变，需要精确命中时用 `[data-dsh-artifact-panel]` 属性选择器。

还有一条互斥要处理：`dsh-web-ui` 家族有一个 `aionui-panel` 右面板提供方，它被选中时我们必须整个不挂载，否则两个面板叠在一起。

**这个判定必须是活的，不能只在启动时算一次。** 用户是在设置里切换提供方的，切换的那一刻两个面板就叠上了。参考实现的做法是订阅运行时的 `settings/document-updated` 广播重新求值并 `unmount()`，拿不到 `remote` 服务的部署才退化成启动时判定。

面板宽度与折叠状态存插件自己的设置里，几何量写成 `<html>` 上的布局变量。这里有个顺带的坑：**首屏要在第一次挂载前把偏好读出来**，否则新会话会先按默认宽度画一帧再跳。但读设置不能无限等——设置路由挂了面板就永远不出现了。参考实现用一个两秒的超时去赛跑，超时就退回 schema 默认值，面板照常挂载。

## 参考实现：dsh-better-sidebar

`github.com/omdsh-dev/DSH-better-sidebar`，MIT，v0.13.0。本文里"已核实的平台事实"多数与它的 `AGENTS.md` 第 7、8 节对应——我们的平台知识本来就与它同源，好处是那些结论有一个在跑的实现背书。借它的代码要注明出处。

**定位不同，可借的只有一半。** 它是本地插件：有 Node 半，直接 `node:fs` 读盘、`node-pty` 开终端、还有 git 面板。我们在沙箱里，走 envd，没有 host 半。所以它的 host 半不可移植，而它的 client 半（约 13000 行）面对的是同一个 dsh 前端，值得逐处对照。

值得学的（本文已分别吸收进对应章节）：body 挂载与互斥的写法、首屏偏好的超时赛跑、令牌"真值但视觉惰性"的判定、`openPath` 包装的放行规则、HTML 路由的路径编解码实现、以及"失败要看得见"——它在客户端生命周期的每个阶段兜住异常并往页面钉一条诊断条，注释写得很好：**空白面板绝不能是唯一的症状**。

明确不学的：

- 它把自己做成了生态底座（`ctx.provide`、对外注册 API、七百行接入文档）。本文的立场相反，见"viewer 是内部注册表"。
- 它长成了工作台——Git 面板、子代理拓扑、拖拽分栏、编辑器与资源管理器二合一，全是本文"明确不做"表里的东西。这不是批评：它每一步都合理，合起来就越过了判据。**这恰好说明那条判据不写下来就守不住。**
- ⚠️ **它的路径栅栏不做 `realpath`**（只有 `isAbsolute` + `resolve` + 前缀比较）。在它的威胁模型下没问题——用户自己的电脑，栅栏防的是 DNS rebinding 和跨站。我们不是，见上面的两条约束。它的前缀比较逻辑本身值得抄：归一化分隔符、去掉尾斜杠、要求 `t === b || t.startsWith(b + '/')`，避免了裸 `startsWith` 会放行 `/mnt/workspace-evil` 的经典 bug。

## 平台硬约束

- **构建纯度门**：client bundle 禁止 value-import `@dsh-external/*` 和非白名单的 `@deepseek-ai/*`；`import type {}` 会被擦除，不触发。
- **ModuleLoader 不跨插件**：跨插件交互只能走方法调用，不能 `require` 对方模块。
- **皮肤是令牌驱动的**：只消费 `--dsw-alias-*` / `--dsw-font-*` / `--ds-*`，不硬编码颜色，不做每皮肤适配。特别地——**绝不消费 `--dsw-specific-sidebar-fill`**，那是宿主左侧导航列的专属令牌，有皮肤把它设成 `transparent`。面板表面用 `--dsw-alias-bg-layer-1`。
- **先看源码，不要从运行时反推。** `~/Workspace/opensource/deepseek-harness` 是这套前端的源码仓库，CSS Modules 原文都在里面（标题栏是 `packages/client/ui-conversation/src/client/skeleton/ConversationRoot.module.css`，左栏新会话按钮是 `packages/client/ui-sidebar/src/client/SidebarRoot.module.css`，Session log 按钮是 `packages/session-query/session-log-export/src/client/HeaderAction.module.css`）。要跟某个元素对齐或一致时，读它的规则、用它的 token，别照着 `getComputedStyle` 的结果重新拼一套——量出来的是结果，源码里写的是意图。
- **令牌名必须核过才能用。** 这条已经栽过两次。`--dsw-alias-button-ghost-hover-fill` 和 `--dsw-alias-fill-tertiary` 都是想当然写出来的，源码里根本不存在，于是 `var(名字, 字面值)` 里的字面值一直在生效——注释写着"跟随皮肤"，实际是硬编码。真实的是 `--dsw-alias-interactive-bg-hover`（悬浮）和 `--dsw-alias-button-ghost-active-fill`（按下/凹槽）。核的办法：`grep -r -- '--dsw-alias-<名字>' deepseek-harness/packages`，再在真实浏览器里确认它在 `body` 上有值——两者都过才算存在。**核过之后就别再写字面回退了**，写了只会把下一次的缺失重新藏起来。
- **半透明表面要回退**：文本类表面读到 alpha < 0.9 的玻璃值时回退不透明底色，否则文字会叠在皮肤背景上滚动。**注意这个回退不能靠 `读令牌() || 兜底` 写**——`transparent` 和 `rgba(...,0.16)` 都是真值字符串，`||` 永远不触发。要有一个"这个值到底画不画得出东西"的判定：空串、`transparent`、各种 unset 关键字、以及 alpha 低于阈值的颜色一律当成没读到，返回空串让兜底链接上；≥0.9 的近不透明值放行，皮肤仍然可控。同一类故障的另一面是**令牌名写错**——不存在的令牌解析成空串，硬编码的颜色于是永远生效，而注释还写着"跟随皮肤"。新引入任何令牌名，先在真实浏览器里 `getComputedStyle(document.body).getPropertyValue(名字)` 确认它有值。
- **i18n 跟随 `ctx.locale`**，不是浏览器语言。

## 包结构与一个待定的取舍

```
packages/dsh-artifact-panel/
  client.js     纯浏览器包：面板外壳 + tab 栏 + viewer
  package.json

gateway/src/
  envd.js       补 readFile / stat / listDir（控制台再加流式）
  panel.js      /sandbox/fs/*、/sandbox/raw/* 路由与路径守卫
```

包里没有 host 半——见上。

**待定：要不要引入构建步骤。** `dsh-sandbox-host` 的模块注释写明：客户端模块注册表逐字提供插件的 `client` 导出，不经过 node_modules 解析，没有构建步骤。照这个约定，`client.js` 只能手写 `React.createElement`，不能用 JSX 或 TypeScript。

- **不引入**：和现有两个包一致，零构建，镜像和 CI 不用动。代价是 tab 栏、树、几个 viewer 全用 `createElement` 写。
- **引入**：开发体验好得多，但会是 `packages/` 下第一个有构建产物的包，Dockerfile 的 `--install-links` 安装和 CI 的产物检查都要跟着改。

**建议先不引入**，等 `client.js` 超过约 1500 行再重新评估。

## viewer 是内部注册表，不对外

一个数组，每项 `{ match(path, mime), component }`，加一种类型等于加一个文件。**不 `ctx.provide` 服务、不发类型声明、不写外部接入文档。**

第三方扩展不是 HamsterHQ 的产品目标。真有需求时再把内部数组升格成服务，那时的迁移成本远小于现在维护一套公开 API 的成本。

首发四个：markdown、文本/代码、图片、HTML。其余类型落到"下载"兜底。

## 宿主聊天界面的改造（性质不同，单独对待）

除了面板本身，还要动 dsh 自己的聊天界面：

1. **"对话 / 轨迹"切换目前独占一整行高度**，应与"标准模式"并入同一行，把那一行的高度释放给对话内容。
2. **"session log"按钮缩小**，从现在的位置移到"轨迹"附近、标题栏左侧区域。
3. **在原 session log 的位置放面板开关**。

**这三条和面板本身是两类工作，必须分开看待。** 面板是我们自己挂一个 body 级宿主，里面的一切归我们管；改造聊天界面是**在我们不拥有的组件上做手术**——移动按钮、改变行布局、缩小控件，靠的是 DOM 结构和 CSS 选择器，而这两样上游随时会变，且不会有任何变更通知。

因此对这部分的要求比面板本身严格：

- **结构化选择器，不吃类名**。CSS Modules 的哈希类名不是契约；能用 `:has()` 和元素关系表达的，就不要写类名。
- **失败必须是降级而不是破相**。选择器没命中时，界面应保持上游原样——两个按钮各占一行，难看但可用。绝不能出现按钮消失、重叠或错位。
- **每一处都要能独立关闭**。三条改造各自带开关，一条失效不牵连其余。
- **这部分优先级最低**。它是体验优化，不是产品成立的前提；面板不依赖它。
