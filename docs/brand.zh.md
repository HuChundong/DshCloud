# HamsterHQ 品牌与仓鼠形象规范

[English](brand.md) | 中文

本文是 HamsterHQ 仓鼠形象的规范来源。产品标志、账户头像、生态 Banner 和能力插图应当让人
看出属于同一角色，但不要求用同一张图承担所有用途。

## 标准角色

标准形象是一只紧凑的侧身仓鼠：背部圆润、口鼻短、单圆眼、环形耳朵，两只脚真实着地。
下腹是独立的浅色区域，不是在实心身体上随意加的一条线。动作或道具变化后，身体重心仍须
符合物理规律。

所有变体都要保留这些识别点：

- 不出现跑轮、长尾巴、突出的门牙或老鼠式尖脸；
- 耳朵连接头顶，开口朝向后方；
- 胸口自然连接前脚，后腿承接后脚，不能把脚画成悬空线条；
- 肚皮始终能和上半身毛色区分；
- 道具只用来说明动作，不能遮掉脸、肚皮或着地轮廓。

中立侧身姿态以 [`../gateway/assets/hamster.svg`](../gateway/assets/hamster.svg)
中的几何形状为准。

## 主标志

`gateway/assets/hamster.svg` 是透明底、单色的产品主标志。外轮廓和内轮廓使用曲率连续的
三次贝塞尔样条。身体内部和肚皮均为透明镂空；一条圆头弧线标明肚皮，眼睛使用实心圆。

- 浅色表面使用墨黑 `#101113`。
- 深色表面使用暖白 `#F4F4F2`。
- 原生宽高比为 `1200:746`，约 `1.61:1`，禁止拉伸。
- 完整主标志建议不小于 20 px 高；更小的方形位置使用
  `gateway/assets/favicon.svg`。
- 背景保持透明，不添加身体填色、渐变、阴影、外框或第二种描边颜色。
- 所有尺寸共用同一套轮廓。主标志不高于 40 px（或不宽于 64 px）时增加 16 单位的
  光学补偿描边，并把肚皮弧线从 24 单位加粗到 38 单位，避免栅格化后细节发虚。
- favicon 在方形 viewBox 中复用同一路径，但小尺寸补偿更强：不大于 64 px 时增加
  40 单位的光学描边，肚皮弧线使用 56 单位。

SVG 是唯一的几何源。页面应直接把它作为图片引用，不要在每个使用方复制一份路径数据。

## 文字标识

名字由两部分组成,也照两部分来排:**Hamster** 是词,**HQ** 是压在它上面的标记——
从一个圆角墨块里反白出来。

和上面那枚标识一样是单色,用的是同两种颜色:墨黑 `#101113` 与暖白 `#F4F4F2`。
两者成对翻转,所以浅色底上是墨块、深色底上是暖白块。整个组合里不引入第三种颜色;
强调绿属于产品状态(比如运行中的沙箱),不属于名字。

三条规则让它在任何尺寸下都是同一个形状:

- 用 `em` 计量,所以登录页的 1.5rem 和侧边栏的 15px 是同一个组合,而不是两套设计;
- 圆角块上写 `letter-spacing: 0`,因为整个词用的负字距会把 `H` 和 `Q` 挤到一起;
- 圆角块上写 `line-height: 1`。若继承行高,它的盒子高度是**一行文字**的高度而不是字母的高度,
  于是上下各多出一段它用不上的行距。

它在每个表面上只定义一次并复用:网关渲染的页面用 `gateway/src/page-chrome.js` 里的
`WORDMARK` 和 `BRAND_CSS`,前门用 `web/landing/styles.css` 里的 `.word-hq`,应用外壳用
`packages/dsh-brand/client.js` 里的 `BrandName`——它用不了那些 token,因为那是本部署的,
所以它自带这两种颜色,并按 `body[data-ds-dark-theme]` 翻转。

## 应用的中性色

外壳自带的灰阶偏蓝——每一级的蓝都比红多,浅端多 2、中段多到 15。前门不是:它的纸面是
偏暖的米白。两者并排,看起来像两个产品。所以 `packages/dsh-brand/client.js` 用一套暖灰
替换掉那条色阶。

变的只有色温。每一级都保持原有亮度(算出来的,不是看出来的),所以界面里的每一个对比度
仍是上游定的那个——抽查的几组变化不到百分之一。只有两级是钉死而非换算的:最浅的是白,
最深的是品牌墨色 `#101113`,也就是前门排正文用的颜色。

被覆盖的是色阶本身,而不是建立在它之上的七十八个 alias——那些是 `var()` 引用,会自动跟随。
强调色和状态色不是中性色,原封不动:运行中的沙箱还是原来那个绿。

## 填充式角色与场景

填充式插图是独立的插画家族，不是线稿主标志的位图版本。统一使用暖纸色背景、暖白和浅暖灰
毛色、灰蓝描边，并只把绿色作为强强调色。造型保持平面、柔和、圆润，纹理和阴影要克制；
避免霓虹色、亮面 3D、写实摄影、玻璃面板或密集的科技界面。

- `web/landing/avatar.webp` 是 128 px 的账户头像。紧凑裁切和绿色底色是刻意设计，不能用
  横向线稿 Logo 替代。
- `docs/assets/dshcloud-banner.webp` 表现多个仓鼠在独立生态舱中围绕共享网关活动。生态舱
  代表相互隔离的沙箱，不能画成笼子或跑轮场景。
- `web/landing/images/work-build.webp` 用仓鼠、简化笔记本和多端产物表达产品构建。
- `web/landing/images/work-research.webp` 用放大镜、笔记和资料表达调研。
- `web/landing/images/work-data.webp` 用散乱素材、规整表格和导出结果表达数据处理。
- `web/landing/images/work-scripts.webp` 用定时输入、处理步骤、运行控件和结果图表达自动化。
- `web/landing/images/work-repo.webp` 用文件夹和相连洞穴表达仓库阅读与导航。

电脑和工具应当简化外形。屏幕不必放装饰性代码或无法阅读的文字，仓鼠的动作本身就应说明
对应能力。

## 创建新姿势

先从标准身体结构出发，调整重心和四肢，再添加道具。坐立、站立、看书、写代码或戴墨镜时，
前爪和脊背可以变化，但脚仍要支撑身体，肚皮仍属于躯干。每张图只表达一个明确动作，并用
尽量少的线条讲清楚。

生成一组姿势或宫格时：

1. 眼睛、耳朵、轮廓粗细、肚皮处理和配色保持一致；
2. 通过姿势和道具制造变化，不改变角色物种；
3. 道具保持次要，小尺寸下删掉不必要的细节；
4. 每个结果都要同时对照标准 SVG 和至少一张已确认的填充式场景。

## 复核清单

接受主标志修改前，必须在浅色和深色背景下渲染。favicon 检查 16、32 px 方形尺寸；主标志
检查 20、24、28、36、48、64、96 px 高度。重点查看头部、耳朵、背线、肚皮连接处和前后脚，
确认没有平点、自交环或突兀曲率。还要和上一版确认过的轮廓做像素对比；为了获得更平滑的
曲线，可以移动少量边缘像素，但不能改变整体姿态。

运行覆盖这些资源和文档的仓库检查：

```sh
xmllint --noout gateway/assets/hamster.svg gateway/assets/favicon.svg
node scripts/check-landing.mjs
node scripts/check-docs.mjs
npx oxlint packages/dsh-brand/client.js
npm --prefix web/landing run build
git diff --check
```

只要身体结构、配色、资源职责或复核流程发生变化，就要同时更新本文和
[英文版本](brand.md)。
